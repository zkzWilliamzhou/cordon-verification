Cordon architecture review

2026-11-11 · v0.1 · vocabulary from GLOSSARY.md and codebase-design · ADRs in docs/adr/

The review walks the modules that changed during the nine review rounds and asks where one concept forces a reader to jump between files. Each card names a deepening opportunity: a refactor that makes a shallow module deep. The report is self-contained and offline; inline CSS and hand-drawn SVG replace the CDN frameworks so the artefact stays reproducible in this sandbox.

C1 — Give inspection one interface Strong

Files
src/cordon/scan.py src/cordon/manifest.py src/cordon/inspector.py (new)
Problem
scan_lines(lines) and extract_entities(files) both own a line model. manifest.derive calls the second one, so Cordon parses every skill file twice. The seam between a detection rule and a derived capability is implicit: a change to the line model can change findings and capabilities differently. Understanding one concept takes two passes through two functions.
Solution
Create one deep module, inspector, with the interface inspect(files) -> Inspection(findings, entities, errors). It owns the line model, the rules and the candidate extraction. scan becomes a thin adapter over fs and inspector. Keep scan_lines and extract_entities as compatibility adapters so the interface stays the test surface.
Benefits
Locality: one walk of one line model produces both outputs. Leverage: one rule change reaches findings, the manifest and every adapter behind the same seam. Depth: a large implementation hides behind one call. Deletion test: removing inspector would move the line model back into two callers rather than concentrate it, which is the signal to keep it.

Before

Two line walks, two owners of the same concept.

After

One interface, one walk, two outputs.

C2 — Make the exec decision a real seam Strong

Files
src/cordon/hook.py src/cordon/guard.py src/cordon/policy.py (new)
Problem
hook._bash checks exe not in caps["exec"]["allow"]. guard.run_shim repeats the same check plus BLOCK_SHIMS. Two adapters, one rule, two implementations. A disagreement between them would produce different verdicts for the same manifest.
Solution
Add a deep policy module with exec_verdict(manifest, name, extra_deny). Both adapters call it. One adapter would be a hypothetical seam; the hook and the shim make it real.
Benefits
Leverage: a policy change reaches both harness seams at once. Locality: the rule and its reason sit in one place. The conformance test compares the two adapters on the same three calls.

Before

Two copies of one decision.

After

Two adapters, one seam.

C3 — Deepen manifest derivation Worth exploring

Files
src/cordon/manifest.py
Problem
derive mixes candidate classification, operator grants and note construction in one long function. A grant loop builds a throwaway list for fs.write and then computes fs_write a second time. The reader has to hold two versions of the same value in their head.
Solution
Keep the public interface derive(scan, grants). Move each candidate class into a small helper behind that interface and compute fs_write once. Preserve the exact derived records and the sorted capabilities so the golden snapshot stays byte-identical.
Benefits
Depth rises without widening the interface. Locality: each decision sits with the candidate class it belongs to. ADR-0005 gates the change with the golden proof.
ADR check
No conflict. ADR-0002 fixes the output format, not the internal module shape.

Top recommendation

Do C1 first, then C2, then C3. C1 removes a duplicated line walk and gives the whole program one inspection seam; C2 turns a duplicated rule into a tested adapter seam; C3 then shortens the remaining long function. Each step runs scripts/golden.py before and after. A byte difference in golden_after.json sends the refactor back. No function of the program changes.

This report does not propose new interfaces for external users. The two published formats stay frozen at v1.
